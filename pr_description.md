⚡ Optimize File Deletion in Updater Background Download

💡 **What:** Replaced synchronous `std::fs::remove_file` calls with `tokio::fs::remove_file(...).await` inside the async `download_inner` function in `src-tauri/src/updater_bin.rs`.
🎯 **Why:** To prevent blocking the async runtime executor thread. Because the `download_inner` function is asynchronous and orchestrated by Tokio, using synchronous I/O operations forces the executing worker thread to block while waiting for the OS, rather than yielding execution. While this function runs as a background task, blocking threads can cause latency spikes, UI stutters, or delays in processing other async operations within the app.
📊 **Measured Improvement:** No direct, meaningful performance improvement metric can be provided for this change because this is a desktop application where these operations happen intermittently (updater downloads), and the file system operations (deleting a single temporary file) are typically in the single-digit millisecond range. The primary value of this fix is architectural correctness (not blocking async threads) rather than achieving a measurable FPS bump or reducing execution time in a heavily concurrent environment.
